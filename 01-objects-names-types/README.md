# 第 1 章 · 对象、名字与类型

> **卷一 · 语言**　|　前置知识：第 0 章　|　建议用时：40 分钟

> 在 Python 里，变量不是盒子，而是贴在对象上的名字。

第 0 章让程序说出了第一句话。这一章要问一个更底层的问题：`x = 42` 到底做了什么？`x` 是“装 42 的盒子”，还是“指向 42 的名字”？为什么 `a = b` 之后修改 `a`，有时 `b` 也会变？`is` 和 `==` 到底差在哪里？

这一章只讲语言本身：对象、名字、类型、身份、可变性、哈希和拷贝。函数调用、类和垃圾回收的更多细节留到后面。

## 1.2 对象与名字

Python 里**一切都是对象**。数字、字符串、函数、类、模块、类型本身，都是对象。对象有三个基本属性：

1. **身份**（identity）：它是哪一个对象，用 `id()` 查看；
2. **类型**（type）：它是什么，用 `type()` 查看；
3. **值**（value）：它表示什么。

赋值语句：

```python
x = 42
```

不是“把 42 放进盒子 x”，而是：

1. 创建一个整数对象 `42`（如果还没有可复用的对象）；
2. 把名字 `x` 绑定到这个对象上。

名字和对象之间是**绑定**关系，不是包含关系。一个对象可以有多个名字：

```python
x = [1, 2, 3]
y = x
```

现在 `x` 和 `y` 指向同一个列表对象。通过 `x` 修改列表，`y` 也会看到变化：

```python
x.append(4)
print(y)   # [1, 2, 3, 4]
```

赋值 `y = x` 没有复制列表，只是让 `y` 也绑定到同一个对象。

### 重新绑定与修改

有两种看起来相似、实际完全不同的操作：

```python
x = [1, 2, 3]
y = x

x.append(4)   # 修改对象：y 也能看到
print(x, y)   # [1, 2, 3, 4] [1, 2, 3, 4]

x = [9, 9]    # 重新绑定名字：y 仍然指向旧对象
print(x, y)   # [9, 9] [1, 2, 3, 4]
```

- **修改**（mutation）改变对象本身；
- **重新绑定**（rebinding）改变名字指向哪个对象。

理解这两者的区别，是理解 Python 可变性、函数参数和别名的第一步。

### `del` 删除的是名字

```python
x = [1, 2, 3]
del x
# print(x)  # NameError
```

`del x` 删除名字 `x` 的绑定，不会立刻“销毁”对象。如果还有别的名字指向它，对象仍然活着：

```python
x = [1, 2, 3]
y = x
del x
print(y)   # [1, 2, 3]
```

对象什么时候销毁？当没有任何可达引用时，由垃圾回收机制处理。CPython 主要使用引用计数，辅以循环垃圾回收；其他实现可能不同。语言规范不保证析构的精确时机。

## 1.3 身份、相等与 `is`

`==` 比较**值**，`is` 比较**身份**：

```python
first = [1, 2]
second = [1, 2]
third = first

first == second   # True：内容相同
first is second   # False：不是同一个对象
first is third    # True：同一个对象
```

`is` 等价于比较 `id(first) == id(second)`，但更直接。

### 什么时候用 `is`

`is` 主要用于与单例对象比较：

```python
value = None
if value is None:
    ...

flag = True
if flag is True:   # 可以，但通常 if flag: 更自然
    ...
```

不要用 `is` 比较数字和字符串的值：

```python
a = 1000
b = 1000
a is b        # 可能是 True，也可能是 False，取决于实现和优化
a == b        # 一定按值比较
```

CPython 会缓存一些小整数（常见是 -5..256）和某些字符串，但这是**实现细节**，不是语言保证。依赖 `is` 判断值相等，会让代码在不同实现、不同版本、不同优化级别下表现不同。

Python 3.8 起，对字面量使用 `is` 可能产生 `SyntaxWarning`：

```python
if x is 1:     # 警告：is 应与单例比较
    ...
```

写 `x == 1`。

### `None` 是单例

`None` 是 `NoneType` 的唯一实例。语言保证 `None is None`。因此 `is None` 是惯用写法，比 `== None` 更明确，也避免自定义 `__eq__` 带来的意外。

`True` 和 `False` 也是单例，但通常直接写 `if flag:` 就够了。

## 1.4 类型：动态而强

Python 是**动态类型**语言：名字不绑定类型，运行时才检查对象的类型。

```python
value = 42
value = "hello"
value = [1, 2, 3]
```

同一个名字可以依次绑定到不同类型的对象。类型属于对象，不属于名字。

Python 也是**强类型**语言：不同类型之间的操作不会自动做“合理”的隐式转换。

```python
"1" + 1        # TypeError
1 + "1"        # TypeError
int("1") + 1   # 2，显式转换
```

“动态”说的是类型检查发生在运行时；“强”说的是不会随便把字符串当数字。两者不是一回事。

### 常见内置类型

| 类型 | 字面量示例 | 可变？ | 可哈希？ |
|------|------------|--------|----------|
| `int` | `42`、`0x2A`、`0b101010` | 否 | 是 |
| `float` | `3.14`、`1e3` | 否 | 是 |
| `bool` | `True`、`False` | 否 | 是 |
| `complex` | `1 + 2j` | 否 | 是 |
| `str` | `"hello"` | 否 | 是 |
| `bytes` | `b"hello"` | 否 | 是 |
| `bytearray` | `bytearray(b"hello")` | 是 | 否 |
| `list` | `[1, 2, 3]` | 是 | 否 |
| `tuple` | `(1, 2, 3)` | 否 | 元素可哈希时可哈希 |
| `dict` | `{"a": 1}` | 是 | 否 |
| `set` | `{1, 2, 3}` | 是 | 否 |
| `frozenset` | `frozenset({1, 2})` | 否 | 是 |
| `NoneType` | `None` | 否 | 是 |

`bool` 是 `int` 的子类：

```python
isinstance(True, int)   # True
True == 1               # True
True + 1                # 2
```

这让 `True` 可以在很多整数位置使用，但也意味着不要把布尔值和整数混为一谈。

### `type` 与 `isinstance`

```python
type(42) is int          # True
isinstance(42, int)      # True
isinstance(True, int)    # True
type(True) is int        # False
```

`isinstance` 会考虑继承关系，通常更适合做类型判断；`type(x) is T` 要求精确类型。需要排除子类时用后者，否则优先用 `isinstance`。

## 1.5 可变与不可变

**不可变对象**创建后不能改变值：

- `int`、`float`、`complex`
- `bool`
- `str`、`bytes`
- `tuple`、`frozenset`
- `None`

**可变对象**可以在原地修改：

- `list`
- `dict`
- `set`
- `bytearray`
- 大多数用户自定义类的实例

```python
text = "hello"
upper = text.upper()   # 返回新字符串，不修改 text
print(text, upper)     # hello HELLO
```

字符串的 `+=` 会创建新字符串，而不是原地修改：

```python
text = "a"
alias = text
text += "b"
print(text, alias)     # ab a
```

列表的 `+=` 通常原地扩展：

```python
values = [1]
alias = values
values += [2]
print(values, alias)   # [1, 2] [1, 2]
```

### 不可变不等于“内部一切都不能变”

元组本身不可变，但如果它包含可变对象，内部对象仍然可以变：

```python
pair = (1, [2, 3])
pair[1].append(4)
print(pair)   # (1, [2, 3, 4])

pair[0] = 99  # TypeError
```

“不可变”指的是元组自己的元素引用不能替换，不是递归地冻结所有嵌套对象。

### 为什么可变性重要

可变性影响：

- 函数调用时实参是否会被修改；
- 对象能否作为字典键或集合元素；
- 多线程/多进程共享数据是否安全；
- 缓存、默认参数、类属性是否会被意外共享。

第 4 章会讲“可变默认参数”这个经典陷阱；第 7 章会讲类属性与实例属性的共享问题。

## 1.6 哈希与可哈希性

哈希把对象映射成一个整数，用于字典和集合的快速查找：

```python
hash(42)
hash("abc")
hash((1, 2))
```

可哈希的对象必须满足：

1. 在其生命期内哈希值不变；
2. 相等的对象必须有相等的哈希值（`a == b` 推出 `hash(a) == hash(b)`）。

因此：

- 不可变的内置类型通常可哈希；
- 可变容器（`list`、`dict`、`set`）不可哈希；
- 元组只有所有元素都可哈希时才可哈希；
- 自定义类默认按身份哈希；如果你定义了 `__eq__` 而没有定义 `__hash__`，Python 会把该类设为不可哈希。

```python
mapping = {}
mapping["a"] = 1
mapping[(1, 2)] = "tuple key"

mapping[[1, 2]] = "bad"   # TypeError: unhashable type: 'list'
```

### 哈希随机化

CPython 默认对 `str` 和 `bytes` 的哈希做随机化，导致同一个字符串在不同进程中的 `hash()` 值可能不同。这是为了防止哈希碰撞攻击，不是语言规范要求的行为。

因此：

- 不要把 `hash("...")` 的结果持久化；
- 不要依赖字典/集合的迭代顺序来获得“哈希顺序”；
- 字典保证插入顺序，但集合不保证顺序。

## 1.7 拷贝：浅与深

赋值不是拷贝：

```python
original = [1, 2, 3]
alias = original
```

如果需要独立副本，可以用：

```python
copy1 = original.copy()
copy2 = original[:]
copy3 = list(original)
```

这些都是**浅拷贝**：只复制最外层容器，内部元素仍然是同一个对象。

```python
original = [[1, 2], [3, 4]]
shallow = original.copy()

original[0].append(99)
print(shallow)   # [[1, 2, 99], [3, 4]]
```

**深拷贝**递归复制内部对象：

```python
from copy import deepcopy

deep = deepcopy(original)
original[0].append(100)
print(deep)      # 不受影响
```

选择：

- 容器里只有不可变对象：浅拷贝通常够用；
- 容器嵌套且需要完全独立：用 `deepcopy`；
- 对象包含文件、锁、网络连接等不可复制资源：不要盲目 `deepcopy`。

## 1.8 函数调用中的对象

Python 的参数传递既不是 C 的按值复制，也不是 C++ 的引用参数。更准确的说法是：**函数收到的是对象引用的副本**，有时被称为“按对象引用传递”或“call by sharing”。

```python
def mutate(values):
    values.append(100)

data = [1, 2, 3]
mutate(data)
print(data)   # [1, 2, 3, 100]
```

函数内的 `values` 和外面的 `data` 指向同一个列表，所以修改可见。

但重新绑定形参不会影响调用者：

```python
def rebind(values):
    values = [7, 8, 9]

data = [1, 2, 3]
rebind(data)
print(data)   # [1, 2, 3]
```

`values = [...]` 只是让局部名字指向新对象，外面的 `data` 仍然指向旧对象。

这条规则适用于所有对象：

- 可变对象可以被函数原地修改；
- 不可变对象不能被修改，函数只能返回新对象；
- 重新绑定形参永远不影响调用者的名字（除非用可变容器或 `global` 等显式机制）。

第 4 章会从作用域和闭包的角度再讲一遍。

## 1.9 几个实现细节

下面这些是 CPython 的常见行为，不是 Python 语言的保证：

- 小整数缓存（常见 -5 到 256）；
- 字符串 intern；
- 引用计数与循环垃圾回收；
- `id()` 在对象销毁后可能被复用；
- 空元组、空字符串等单例优化。

你可以观察它们，但不要依赖它们写业务逻辑。比如：

```python
a = 256
b = 256
a is b        # CPython 通常 True

a = 257
b = 257
a is b        # 可能是 True（同一代码对象常量折叠），也可能 False
```

值相等用 `==`；身份相等才用 `is`。

## 1.11 常见陷阱

| 写法 | 问题 | 建议 |
|------|------|------|
| `b = a` 后修改 `b`，以为 `a` 不变 | 赋值不是拷贝 | 需要独立副本时显式 `copy` / `deepcopy` |
| 用 `is` 比较数字/字符串 | 身份不是值 | 用 `==`；`is` 只用于 `None` 等单例 |
| `list` 作为字典键 | 不可哈希 | 用元组、字符串或自定义不可变键 |
| 用 `hash("...")` 持久化 | 哈希随机化 | 用稳定摘要（如 hashlib） |
| 浅拷贝嵌套列表 | 内部对象仍共享 | 需要完全独立时 `deepcopy` |
| 认为元组完全不可变 | 嵌套可变对象仍可改 | 区分“引用不可变”和“递归不可变” |
| `del x` 以为销毁对象 | 只删除名字 | 让所有引用消失，或交给 GC |
| 用 `type(x) is int` 判断所有整数 | 排除 `bool` 子类 | 通常用 `isinstance` |
| 依赖小整数缓存 | 实现细节 | 值比较用 `==` |
| 认为 `True` 和 `1` 完全一样 | 值相等但类型不同 | 不要把布尔当整数滥用 |

## 1.12 语法卡片

| 术语 | 一句话定义 | 本章例子 |
|------|------------|----------|
| 对象 | 有身份、类型和值的运行时实体 | `[1, 2, 3]` |
| 名字 | 绑定到对象的标识符 | `x = 42` |
| 身份 | 对象是哪一个 | `id(x)`、`x is y` |
| 类型 | 对象是什么 | `type(x)` |
| 可变对象 | 可以原地修改 | `list`、`dict`、`set` |
| 不可变对象 | 创建后不能修改值 | `int`、`str`、`tuple` |
| 哈希 | 把可哈希对象映射为整数 | `hash(x)` |
| 浅拷贝 | 只复制最外层容器 | `original.copy()` |
| 深拷贝 | 递归复制内部对象 | `deepcopy(original)` |
| 别名 | 多个名字指向同一对象 | `y = x` |

## 1.13 练习

1. **别名**：创建 `a = [1, 2]`、`b = a`，分别用 `b.append(3)` 和 `b = b + [4]` 修改，打印 `a` 和 `b`，解释差异。
2. **身份**：对 `None`、`True`、小整数、大整数、字符串、列表分别比较 `is` 和 `==`，记录哪些结果依赖实现。
3. **可变性**：定义一个元组 `(1, [2, 3])`，尝试修改第一个元素和内部列表，解释哪个成功、哪个失败。
4. **哈希**：用 `hash()` 计算几个值；尝试把列表放进集合，读 `TypeError`。
5. **拷贝**：构造嵌套列表，分别用赋值、切片、`copy.copy`、`deepcopy` 创建四个变量，修改原列表并比较结果。
6. **函数参数**：写一个函数原地修改列表，再写一个函数重新绑定形参，验证调用者的对象是否变化。
7. **引用计数**：在 CPython 中用 `sys.getrefcount(x)` 观察别名增加时的计数变化（结果包含临时引用，别把它当精确值）。
8. **破坏实验**：把 `a is b` 用于两个值相等的字符串，观察结果；再换成 `==`，说明为什么后者才是正确写法。
